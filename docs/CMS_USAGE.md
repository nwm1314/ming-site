# CMS 使用说明

## 进入后台

1. 打开网站地址后，在末尾加上 `/admin`。
2. 点击 **Sign In with Token**。
3. 按 GitHub 页面提示创建只用于这个公开仓库的访问 Token，并粘贴回登录框。
4. Token 只保存在当前浏览器中，不要写进文章、配置文件、截图或仓库。

后台已经设置为简体中文浏览器优先使用中文。也可以在后台的个人设置里切换语言。

## 更新 Now

打开 **现在 / Now**，直接修改 **Building**、**Exploring**、**Learning** 三块文字和更新时间，然后点击保存。后台会把修改提交到 GitHub；Cloudflare 完成构建后，网站就会更新。通常需要几分钟，具体取决于当时的构建队列。

## 写文章和发布

1. 打开 **文章**，点击新建。
2. 填标题、摘要、日期、分类、标签和正文；需要时上传封面。
3. 新文章默认勾选 **草稿**，保存后不会公开。
4. 确认内容后取消 **草稿**，再次保存，构建完成后才会发布。

文章的 `publishDate` 不能晚于构建时间，否则也不会进入公开列表。

需要离线起草时，也可以复制 `templates/content/post.md`、`moment.md` 或 `project.md`。模板不属于生产内容；命令行还提供 `pnpm new:post` 和 `pnpm new:moment`，会询问标题、slug 和日期，并拒绝覆盖已有文件。

## 修改项目、工具和其他内容

- **项目**：使用状态下拉选项，不要自己拼写状态值。
- **Uses**：填写正在使用的工具和用途，不填写技能等级。
- **动态**：新内容默认仅链接可见；确认无误后才选择公开。
- **相册**：上传图片并填写替代文字、相册、日期和地点。
- **时间线**：只添加真实节点。

## 上传图片

在图片字段或媒体库选择上传。图片会提交到仓库的 `public/uploads/`，之后由 Cloudflare Static Assets 发布。头像推荐正方形 WebP，建议不超过 500 KB；不要直接上传几 MB 的原图。

仓库会运行确定性的媒体大小检查：普通图片超过 5 MiB 会给出警告，超过 20 MiB 会让质量检查失败；站点头像有明确的 2 MiB 警告 / 5 MiB 失败阈值，默认 OG 图有单独的显式策略。检查只报告，不会压缩或修改上传文件。若 CI 报错，按错误信息中的完整路径处理后再提交。

文章封面必须同时填写 `coverAlt`；相册图片必须填写 `alt`。这些字段与 Astro schema 同步校验，避免发布后才发现无替代文字。

## 构建失败怎么办

先打开 GitHub 仓库的 Actions 或 Cloudflare 部署记录，看失败步骤和错误文件。最常见的问题是必填字段为空、日期格式不对、URL 写错，或 Markdown frontmatter 缩进错误。修正后重新保存即可；如果刚才的修改不需要，可以在 GitHub 中恢复对应 commit，再等待下一次构建。

如果 Token 泄露，立即在 GitHub 撤销它，再重新登录后台。不要把 Token 发给别人，也不要提交任何 `.env` 文件。
